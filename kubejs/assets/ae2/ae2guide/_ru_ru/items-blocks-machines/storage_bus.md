# Шина хранения

<GameScene zoom="8" background="transparent">
<ImportStructure src="../assets/blocks/storage_bus.snbt" />
</GameScene>

Хотели когда-нибудь *сохранить* свой монстра-сундук вместо замены на что-то разумное? Представляем шину хранения!

Шина хранения превращает инвентарь, к которому прижата, в [сетевое хранилище](../ae2-mechanics/import-export-storage.md).
Она делает это, позволяя сети видеть содержимое этого инвентаря и вталкивая в него и вытягивая из него,
чтобы выполнять запросы [устройств](../ae2-mechanics/devices.md), вталкивающих в сетевое хранилище и вытягивающих из него.

Из-за философии AE2 — возникновение механик из взаимодействия функций [устройств](../ae2-mechanics/devices.md) — вам не обязательно
нужно использовать шину хранения именно для *хранения*. Используя [подсети](../ae2-mechanics/subnetworks.md),
чтобы сделать шину хранения (или несколько шин хранения) *единственным* хранилищем в сети, вы можете использовать её как источник или приёмник
для передачи предметов. (см. [«трубная подсеть»](../example-setups/pipe-subnet.md))

ВАЖНОЕ ПРИМЕЧАНИЕ: Большие оптимизированные инвентари, например ящики для инструментов, — это нормально, но большие *не*оптимизированные инвентари со множеством слотов, например
колоссальные сундуки, ужасны для производительности при использовании с шинами хранения.

Они являются [субчастями кабеля](../ae2-mechanics/cable-subparts.md).

## Фильтрация

По умолчанию шина будет хранить всё. Предметы, вставленные в её слоты фильтра, действуют как белый список, разрешая
хранение только этих конкретных предметов.

Предметы и жидкости можно перетаскивать в слоты из JEI/REI, даже если у вас на самом деле нет ни одного такого предмета.

Щёлкните правой кнопкой мыши с контейнером для жидкости (например, ведром или резервуаром), чтобы задать эту жидкость как фильтр вместо предмета ведра или резервуара.

## Приоритет

Приоритеты можно задать, щёлкнув по гаечному ключу в правом верхнем углу интерфейса.
Предметы, поступающие в сеть, первым делом будут направляться в хранилище с наивысшим приоритетом. Если два хранилища имеют одинаковый приоритет,
то при наличии предмета в одном из них предпочтение будет отдано этому хранилищу перед любым
другим. Любые отфильтрованные хранилища считаются уже содержащими предмет
при одинаковой группе приоритета с другими хранилищами. Предметы, удаляемые из хранилища, будут
извлекаться из хранилища с наименьшим приоритетом. Благодаря этой системе приоритетов по мере добавления и извлечения предметов
из сетевого хранилища хранилища с более высоким приоритетом будут заполняться, а с более низким — опустошаться.

## Настройки

*   Шину можно разделить (отфильтровать) по тому, что сейчас находится в соседнем инвентаре
*   Сети можно запретить или разрешить видеть предметы в соседнем инвентаре, которые шина не может извлечь
    (например, шина хранения не может извлечь предметы из среднего входного слота <ItemLink id="inscriber" />)
*   Шина может фильтровать и при вставке, и при извлечении, или только при вставке
*   Шина может быть двунаправленной, только на вставку или только на извлечение

## Улучшения

Шина хранения поддерживает следующие [улучшения](upgrade_cards.md):

*   <ItemLink id="capacity_card" /> увеличивает количество слотов фильтра
*   <ItemLink id="fuzzy_card" /> позволяет шине фильтровать по уровню повреждения и/или игнорировать NBT предмета
*   <ItemLink id="inverter_card" /> переключает фильтр с белого списка на чёрный
*   <ItemLink id="void_card" /> уничтожает вставляемые предметы, если подключённый инвентарь полон, полезно для предотвращения забивания ферм. Будьте осторожны и задайте разделение!
